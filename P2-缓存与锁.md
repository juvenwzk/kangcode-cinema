## 1. 本阶段目标

1. 读多写少的接口（车站列表、车次详情）用 **Spring Cache** 自动缓存；
2. 热点数据（余票）用 **StringRedisTemplate 手写缓存**：快、准、防穿透；
3. 放票时把库存 **预热进 Redis**，购票（P3）才扣得动；
4. 用 **定时对账** 兜底缓存与数据库的一致性（Canal 的替代方案）。

---

## 2. 两套缓存怎么分工

| 场景 | 方案 | 为什么这么选 |
| --- | --- | --- |
| 车站列表、车次详情 | Spring Cache（`@Cacheable`） | 数据变化少，注解最省事，key/TTL 统一在 CacheConfig 管 |
| 余票查询 | 手写 `StringRedisTemplate` | 需要空值缓存、互斥重建、TTL 抖动，注解表达不了 |
| 库存扣减 | Redis Lua + Redisson 锁（P3） | 必须原子、防超卖 |
| 库存对账 | `@Scheduled` 定时任务（P2） | Canal 已移除，用"定时勾兑"代替实时同步 |

### 3.1 Spring Cache 配置：`framework/src/main/java/com/kangcode/framework/config/CacheConfig.java`

```java
package com.kangcode.framework.config;

import com.fasterxml.jackson.annotation.JsonAutoDetect;
import com.fasterxml.jackson.annotation.JsonTypeInfo;
import com.fasterxml.jackson.annotation.PropertyAccessor;
import com.fasterxml.jackson.databind.ObjectMapper;
import com.fasterxml.jackson.databind.SerializationFeature;
import com.fasterxml.jackson.databind.jsontype.impl.LaissezFaireSubTypeValidator;
import com.fasterxml.jackson.datatype.jsr310.JavaTimeModule;
import org.springframework.cache.annotation.EnableCaching;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.data.redis.cache.RedisCacheConfiguration;
import org.springframework.data.redis.cache.RedisCacheManager;
import org.springframework.data.redis.connection.RedisConnectionFactory;
import org.springframework.data.redis.serializer.GenericJackson2JsonRedisSerializer;
import org.springframework.data.redis.serializer.RedisSerializationContext;
import org.springframework.data.redis.serializer.StringRedisSerializer;

import java.time.Duration;
import java.util.HashMap;
import java.util.Map;

/**
 * Spring Cache 配置：用 Redis 做缓存后端，支持按 cache name 设置不同过期时间。
 */
@Configuration
@EnableCaching
public class CacheConfig {

    /** Key 前缀，避免和业务手写的 key 冲突 */
    private static final String KEY_PREFIX = "railway:cache:";

    /**
     * 缓存值的序列化器：JSON + 类型信息 + Java8 时间支持。
     * 为什么要自己 new：默认的 GenericJackson2JsonRedisSerializer 内部 ObjectMapper
     * 没有注册 JavaTimeModule，遇到 LocalTime/LocalDateTime 会直接抛异常。
     */
    private GenericJackson2JsonRedisSerializer jsonSerializer() {
        ObjectMapper mapper = new ObjectMapper();
        mapper.registerModule(new JavaTimeModule());                    // 支持 LocalDate/LocalTime
        mapper.disable(SerializationFeature.WRITE_DATES_AS_TIMESTAMPS); // 时间写成可读格式
        mapper.setVisibility(PropertyAccessor.ALL, JsonAutoDetect.Visibility.ANY);
        mapper.activateDefaultTyping(LaissezFaireSubTypeValidator.instance,
                ObjectMapper.DefaultTyping.NON_FINAL, JsonTypeInfo.As.PROPERTY); // 写 @class
        return new GenericJackson2JsonRedisSerializer(mapper);
    }

    @Bean
    public RedisCacheManager cacheManager(RedisConnectionFactory factory) {
        GenericJackson2JsonRedisSerializer valueSerializer = jsonSerializer();
        RedisCacheConfiguration base = RedisCacheConfiguration.defaultCacheConfig()
                .entryTtl(Duration.ofMinutes(10))       // 默认 10 分钟
                .prefixCacheNameWith(KEY_PREFIX)        // railway:cache:
                .serializeKeysWith(RedisSerializationContext.SerializationPair
                        .fromSerializer(new StringRedisSerializer()))
                .serializeValuesWith(RedisSerializationContext.SerializationPair
                        .fromSerializer(valueSerializer))
                .disableCachingNullValues();

        Map<String, RedisCacheConfiguration> configs = new HashMap<>();
        configs.put("station", base.entryTtl(Duration.ofHours(6)));       // 车站：6 小时
        configs.put("train", base.entryTtl(Duration.ofMinutes(30)));      // 车次：30 分钟
        configs.put("ticketStock", base.entryTtl(Duration.ofMinutes(5))); // 余票：5 分钟

        return RedisCacheManager.builder(factory)
                .cacheDefaults(base)
                .withInitialCacheConfigurations(configs)
                .build();
    }
}
```

**这里有两个真实踩过的坑，记住就行**：

1. 缓存的对象（VO）必须有**无参构造**，否则写进去读不回来。所以 `StationVO`、`TrainVO`、`OrderVO`、`UserVO` 上都加了 `@NoArgsConstructor @AllArgsConstructor`（`@Builder` 不会自动生成无参构造）。
2. 序列化器**必须注册 `JavaTimeModule`**，否则 `TrainVO` 里的 `LocalTime startTime` 一写缓存就抛异常。

### 3.4 参考样例：余票缓存 `TicketServiceImpl.queryRemain`（已给你）

这段是"缓存三件套"的标准写法，读懂了 2-2、2-3 就都能写：

```java
private static final String EMPTY_VALUE = "EMPTY";          // 空值标记：防穿透
private static final long STOCK_TTL_SECONDS = 10 * 60;      // 正常 TTL：10 分钟
private static final long TTL_JITTER_SECONDS = 60;          // 抖动上限：防雪崩
private static final long EMPTY_TTL_SECONDS = 60;           // 空值 TTL：60 秒

@Override
public Integer queryRemain(Long trainId, LocalDate travelDate, String seatType) {
    String date = travelDate.toString();
    String key = RedisKeyConstant.ticketLockKey(trainId, date, seatType);

    // 1. 命中缓存直接返回
    String cached = stringRedisTemplate.opsForValue().get(key);
    if (cached != null) {
        return EMPTY_VALUE.equals(cached) ? 0 : Integer.valueOf(cached);
    }

    // 2. 抢"重建锁"，只有一个线程去查库（防击穿）
    String rebuildLockKey = key + "#rebuild";
    Boolean got = stringRedisTemplate.opsForValue()
            .setIfAbsent(rebuildLockKey, "1", 10, TimeUnit.SECONDS);
    if (Boolean.TRUE.equals(got)) {
        try {
            return loadFromDbAndCache(key, trainId, travelDate, seatType);
        } finally {
            stringRedisTemplate.delete(rebuildLockKey);
        }
    }

    // 3. 没抢到锁 → 自旋等缓存建好
    for (int i = 0; i < 5; i++) {
        try {
            Thread.sleep(50);
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
            break;
        }
        cached = stringRedisTemplate.opsForValue().get(key);
        if (cached != null) {
            return EMPTY_VALUE.equals(cached) ? 0 : Integer.valueOf(cached);
        }
    }

    // 4. 兜底：直查 DB
    return loadFromDbAndCache(key, trainId, travelDate, seatType);
}
```

> 注意一个坑（代码里现有，P3 顺手改）：这里的 key 用的是 `RedisKeyConstant.ticketLockKey(...)`，本该用 `ticketStockKey(...)`。**写成锁前缀会让"余票缓存"和"分布式锁"用同一个 key**。P3 写 `buy` 时统一改成 `ticketStockKey`。

### 4.1 完整代码（改完之后整个文件长这样）

```java
package com.kangcode.server.service.impl;

import com.baomidou.mybatisplus.core.conditions.query.LambdaQueryWrapper;
import com.baomidou.mybatisplus.core.metadata.IPage;
import com.baomidou.mybatisplus.extension.plugins.pagination.Page;
import com.kangcode.common.core.ResultCode;
import com.kangcode.common.exception.BusinessException;
import com.kangcode.pojo.entity.Station;
import com.kangcode.pojo.entity.Train;
import com.kangcode.pojo.entity.TrainStation;
import com.kangcode.pojo.vo.TrainStationVO;
import com.kangcode.pojo.vo.TrainVO;
import com.kangcode.server.mapper.StationMapper;
import com.kangcode.server.mapper.TrainMapper;
import com.kangcode.server.mapper.TrainStationMapper;
import com.kangcode.server.service.TrainService;
import lombok.RequiredArgsConstructor;
import org.springframework.cache.annotation.Cacheable;
import org.springframework.stereotype.Service;
import org.springframework.util.StringUtils;

import java.util.Collections;
import java.util.List;
import java.util.Map;
import java.util.function.Function;
import java.util.stream.Collectors;

/**
 * 车次服务实现
 */
@Service
@RequiredArgsConstructor
public class TrainServiceImpl implements TrainService {

    private final TrainMapper trainMapper;
    private final TrainStationMapper trainStationMapper;   // 新增
    private final StationMapper stationMapper;             // 新增

    @Override
    public IPage<TrainVO> pageTrain(int page, int size, String keyword) {
        LambdaQueryWrapper<Train> wrapper = new LambdaQueryWrapper<>();
        wrapper.and(StringUtils.hasText(keyword), q -> q
                        .like(Train::getTrainNo, keyword)
                        .or()
                        .like(Train::getTrainName, keyword))
                .orderByAsc(Train::getTrainNo);

        IPage<Train> entityPage = trainMapper.selectPage(new Page<>(page, size), wrapper);

        // entity -> VO：不把数据库实体直接暴露给前端
        IPage<TrainVO> voPage = new Page<>(entityPage.getCurrent(), entityPage.getSize(), entityPage.getTotal());
        voPage.setRecords(entityPage.getRecords().stream()
                .map(this::toVO)
                .collect(Collectors.toList()));
        return voPage;
    }

    @Override
    @Cacheable(value = "train", key = "#trainId")
    public TrainVO getTrainDetail(Long trainId) {
        Train train = trainMapper.selectById(trainId);
        if (train == null) {
            throw new BusinessException(ResultCode.NOT_FOUND);
        }
        TrainVO vo = toVO(train);
        vo.setStations(listStations(trainId));    // 替换原来的 Collections.emptyList()
        return vo;
    }

    /**
     * 组装经停站：先查 train_station，再一次性查 station，避免在循环里查库（N+1）
     */
    private List<TrainStationVO> listStations(Long trainId) {
        List<TrainStation> trainStations = trainStationMapper.selectList(
                new LambdaQueryWrapper<TrainStation>()
                        .eq(TrainStation::getTrainId, trainId)
                        .orderByAsc(TrainStation::getStationNo));
        if (trainStations.isEmpty()) {
            return Collections.emptyList();
        }

        // 收集 stationId，一次性查出来做成 Map，后面在内存里匹配
        List<Long> stationIds = trainStations.stream()
                .map(TrainStation::getStationId)
                .distinct()
                .collect(Collectors.toList());
        Map<Long, Station> stationMap = stationMapper.selectBatchIds(stationIds).stream()
                .collect(Collectors.toMap(Station::getId, Function.identity()));

        return trainStations.stream().map(ts -> {
            Station station = stationMap.get(ts.getStationId());
            TrainStationVO item = new TrainStationVO();
            item.setStationId(ts.getStationId());
            item.setStationCode(station == null ? null : station.getStationCode());
            item.setStationName(station == null ? null : station.getStationName());
            item.setStationNo(ts.getStationNo());
            item.setArriveTime(ts.getArriveTime());
            item.setLeaveTime(ts.getLeaveTime());
            item.setStopMinutes(ts.getStopMinutes());
            item.setDistanceKm(ts.getDistanceKm());
            return item;
        }).collect(Collectors.toList());
    }

    /** 实体转 VO */
    private TrainVO toVO(Train train) {
        return TrainVO.builder()
                .id(train.getId())
                .trainNo(train.getTrainNo())
                .trainName(train.getTrainName())
                .startStationId(train.getStartStationId())
                .endStationId(train.getEndStationId())
                .startTime(train.getStartTime())
                .endTime(train.getEndTime())
                .status(train.getStatus())
                .build();
    }
}
```

### 4.2 三个要点

1. **先查关联表再查主表**：`train_station` 只存 `station_id`，站名在 `station` 表里，所以要两张表拼起来。
2. **不要在循环里查库**：先把 stationId 收集起来用 `selectBatchIds` 一次查完，再在内存里匹配 —— 这就是常说的"解决 N+1 查询"。
3. **这个方法带 `@Cacheable`**：返回的 `TrainStationVO` 必须能被序列化，用 `@Data`（有无参构造）就没问题。

### 5.3 新增 Service 实现：`server/.../service/impl/StockServiceImpl.java`

```java
package com.kangcode.server.service.impl;

import com.baomidou.mybatisplus.core.conditions.query.LambdaQueryWrapper;
import com.kangcode.common.constant.RedisKeyConstant;
import com.kangcode.common.core.ResultCode;
import com.kangcode.common.exception.BusinessException;
import com.kangcode.pojo.dto.StockPublishRequest;
import com.kangcode.pojo.entity.TrainSeat;
import com.kangcode.server.mapper.TrainSeatMapper;
import com.kangcode.server.service.StockService;
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.springframework.data.redis.core.StringRedisTemplate;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

import java.time.LocalDate;
import java.time.LocalDateTime;
import java.util.concurrent.TimeUnit;

/**
 * 库存服务实现：放票 = 改 DB + 把最新余票预热进 Redis
 */
@Slf4j
@Service
@RequiredArgsConstructor
public class StockServiceImpl implements StockService {

    /**
     * 预热进 Redis 的 TTL。
     * 比余票查询缓存的 10 分钟更长，保证刚放完票不会马上过期。
     */
    private static final long STOCK_CACHE_MINUTES = 30;

    private final TrainSeatMapper trainSeatMapper;
    private final StringRedisTemplate stringRedisTemplate;

    @Override
    @Transactional(rollbackFor = Exception.class)
    public int publish(StockPublishRequest request) {
        LocalDate travelDate = request.getTravelDate();
        // 放历史日期的票没有意义，直接挡掉
        if (travelDate.isBefore(LocalDate.now())) {
            throw new BusinessException(ResultCode.BAD_REQUEST);
        }

        TrainSeat seat = trainSeatMapper.selectOne(new LambdaQueryWrapper<TrainSeat>()
                .eq(TrainSeat::getTrainId, request.getTrainId())
                .eq(TrainSeat::getTravelDate, travelDate)
                .eq(TrainSeat::getSeatType, request.getSeatType()));

        int remain;
        if (seat == null) {
            // 第一次给这个「车次 + 日期 + 席别」放票：插入一条库存记录
            TrainSeat entity = new TrainSeat();
            entity.setTrainId(request.getTrainId());
            entity.setTravelDate(travelDate);
            entity.setSeatType(request.getSeatType());
            entity.setTotal(request.getCount());
            entity.setRemain(request.getCount());
            entity.setPrice(0L);            // 票价由管理端另行维护，这里先给 0
            entity.setVersion(0);
            entity.setStatus(1);
            entity.setUpdateTime(LocalDateTime.now());
            trainSeatMapper.insert(entity);
            remain = request.getCount();
        } else {
            // 已存在：总票数和余票一起加
            seat.setTotal(seat.getTotal() + request.getCount());
            seat.setRemain(seat.getRemain() + request.getCount());
            seat.setUpdateTime(LocalDateTime.now());
            // 实体上有 @Version，这里走乐观锁（MybatisPlusConfig 已注册乐观锁插件）
            trainSeatMapper.updateById(seat);
            remain = seat.getRemain();
        }

        // 预热（写绝对值，不是 INCR）：重复执行结果一样，天然幂等
        String key = RedisKeyConstant.ticketStockKey(
                request.getTrainId(), travelDate.toString(), request.getSeatType());
        stringRedisTemplate.opsForValue()
                .set(key, String.valueOf(remain), STOCK_CACHE_MINUTES, TimeUnit.MINUTES);

        log.info("放票成功 trainId={} travelDate={} seatType={} count={} remain={}",
                request.getTrainId(), travelDate, request.getSeatType(), request.getCount(), remain);
        return remain;
    }
}
```

### 5.5 为什么这样设计

| 设计点 | 原因 |
| --- | --- |
| 先改 DB 再写 Redis | MySQL 是唯一真相；Redis 只是副本，写失败也不影响正确性（还有对账兜底） |
| 用 `set` 写绝对值而不是 `INCR` | 重复放票请求结果一致，算一种幂等 |
| 放票走 `@Transactional` | DB 的 insert/update 要么都成功要么都失败 |
| 用 `@Version` 乐观锁 | 两个管理员同时放票时，先提交的赢，后提交的版本不匹配会更新失败 |

## 6. 任务 2-3：定时对账任务（替代 Canal）

**目标**：每 5 分钟用 MySQL 校准一次 Redis 库存，把"对不上"的缓存修回来。

**新建文件**：`server/src/main/java/com/kangcode/server/task/StockReconcileTask.java`

### 6.1 完整代码

```java
package com.kangcode.server.task;

import com.baomidou.mybatisplus.core.conditions.query.LambdaQueryWrapper;
import com.kangcode.common.constant.RedisKeyConstant;
import com.kangcode.pojo.entity.TrainSeat;
import com.kangcode.server.mapper.TrainSeatMapper;
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.springframework.data.redis.core.StringRedisTemplate;
import org.springframework.scheduling.annotation.Scheduled;
import org.springframework.stereotype.Component;

import java.time.LocalDate;
import java.util.List;
import java.util.concurrent.TimeUnit;

/**
 * 库存对账任务：定时用 MySQL 校准 Redis（替代 Canal 的兜底方案）。
 *
 * <p>重要设计取舍：对账只「收紧」不「放大」。
 * 因为购票是「先扣 Redis、再由 MQ 异步落库」，在消息还没消费时 DB 余票会大于 Redis 余票，
 * 如果直接用 DB 覆盖 Redis，就等于把已经卖出去的票又放回去 → 超卖。
 */
@Slf4j
@Component
@RequiredArgsConstructor
public class StockReconcileTask {

    /** 与 TicketServiceImpl 里的空值标记保持一致 */
    private static final String EMPTY_VALUE = "EMPTY";

    /** 对账范围：今天 ~ 今天 + 14 天 */
    private static final int DAYS_AHEAD = 14;
    /** 对账写回的 TTL */
    private static final long STOCK_CACHE_MINUTES = 30;

    private final TrainSeatMapper trainSeatMapper;
    private final StringRedisTemplate stringRedisTemplate;

    /** 启动 1 分钟后跑第一次，之后每 5 分钟一次 */
    @Scheduled(initialDelay = 60_000, fixedDelay = 5 * 60 * 1000)
    public void reconcile() {
        LocalDate today = LocalDate.now();
        List<TrainSeat> seats = trainSeatMapper.selectList(new LambdaQueryWrapper<TrainSeat>()
                .ge(TrainSeat::getTravelDate, today)
                .le(TrainSeat::getTravelDate, today.plusDays(DAYS_AHEAD))
                .eq(TrainSeat::getStatus, 1));

        int preheated = 0;
        int tightened = 0;
        int inFlight = 0;

        for (TrainSeat seat : seats) {
            String key = RedisKeyConstant.ticketStockKey(
                    seat.getTrainId(), seat.getTravelDate().toString(), seat.getSeatType());
            String cached = stringRedisTemplate.opsForValue().get(key);
            int dbRemain = seat.getRemain();

            // ① 还没预热过 → 补上（属于正常情况，不打 WARN）
            if (cached == null || EMPTY_VALUE.equals(cached)) {
                write(key, dbRemain);
                preheated++;
                continue;
            }

            int redisRemain;
            try {
                redisRemain = Integer.parseInt(cached);
            } catch (NumberFormatException e) {
                log.warn("库存对账发现非法值 key={} value={}，按 DB 覆盖", key, cached);
                write(key, dbRemain);
                tightened++;
                continue;
            }

            if (redisRemain > dbRemain) {
                // ② Redis 比 DB 大：缓存被放大了，收紧到 DB 值（防止超卖）
                log.warn("库存对账收紧 key={} redis={} db={}", key, redisRemain, dbRemain);
                write(key, dbRemain);
                tightened++;
            } else if (redisRemain < dbRemain) {
                // ③ Redis 比 DB 小：通常是"已扣减但订单还没落库"的在途状态，不能放大
                inFlight++;
                log.warn("库存对账发现差异（可能在途） key={} redis={} db={}", key, redisRemain, dbRemain);
            }
        }

        log.info("库存对账完成：检查 {} 条，补预热 {} 条，收紧 {} 条，在途差异 {} 条",
                seats.size(), preheated, tightened, inFlight);
    }

    private void write(String key, int remain) {
        stringRedisTemplate.opsForValue()
                .set(key, String.valueOf(remain), STOCK_CACHE_MINUTES, TimeUnit.MINUTES);
    }
}
```

### 6.2 为什么"只收紧不放大"

假设库存 100，用户买了 1 张：

| 时刻 | DB.remain | Redis.remain | 说明 |
| --- | --- | --- | --- |
| 下单瞬间 | 100 | 99 | Redis 已扣，消息还没落库 |
| 消息落库后 | 99 | 99 | 一致 |

如果对账在"下单瞬间"跑，并且**用 DB 覆盖 Redis**，库存就被改回 100 —— 票已经卖了，库存却显示 100，**超卖**。

所以对账规则定为：

- `Redis > DB` → 缓存被放大，**收紧**到 DB（安全）；
- `Redis < DB` → 可能是正常的在途订单，**只记录 WARN，不修改**；
- Redis 里没有 / EMPTY → 直接**预热**成 DB 值。

> 这也解释了"去掉 Canal 之后"的做法：Canal 是实时同步 binlog，我们用定时勾兑 —— **牺牲一点实时性，换实现简单 + 不超卖**。

## 7. 任务 2-4：写操作要清缓存（`@CacheEvict`）

这一节给你**两个能直接跑的管理接口**：改车次（精确删一个 key）和改车站（清空整个 cache），
代码已实测，验证方法在第 7.6 节。

### 7.1 先说清楚：不写 `@CacheEvict` 会出什么问题

`@Cacheable` 的行为是"第一次查库，之后 30 分钟都读缓存"。看这条时间线：

| 时刻 | 发生了什么 | 前端看到 |
| --- | --- | --- |
| 10:00 | 第一次 `GET /api/train/1`，查库 → 写缓存 `railway:cache:train::1`（TTL 30 分钟） | status = 1（运行） |
| 10:05 | 管理员把车次改成停运，**只改了 DB** | 还是 status = 1 |
| 10:10 | 用户再查，命中缓存（不查库） | **还是 1，看不到停运** |
| 10:30 | 缓存过期 | 终于看到 0 |

**结论**：只要有缓存，写操作就必须负责"让缓存失效"。这就是 `@CacheEvict` 的职责。

### 7.2 三个注解的分工

| 注解 | 执行时机 | 干什么 | 用在哪 |
| --- | --- | --- | --- |
| `@Cacheable` | **先查缓存**，命中就不执行方法 | 读 | 查询方法（站点列表、车次详情） |
| `@CachePut` | **每次都执行方法**，再把返回值写进缓存 | 写＋更新缓存 | 改完想把最新值直接塞进缓存 |
| `@CacheEvict` | 方法执行后（默认）**删掉缓存** | 写 | 改/删数据的方法 ← 本任务用的 |

> 什么时候用 `@CachePut` 而不是 `@CacheEvict`？改完的数据**马上就要被前台读、且你手上就有完整的新对象**时，用 `@CachePut` 省一次查库。
> 拿不准就用 `@CacheEvict` 删掉，让下次查询重新查库 —— 更简单、更不容易出错。

### 7.3 key 必须对得上（最容易错的地方）

`@Cacheable` 和 `@CacheEvict` 是**两个独立的注解**，Spring 不会帮你校验它们指的是同一个 key。写错了不会报错，只是**缓存删不掉**。

| 读方法上的写法 | 实际 Redis key | 写方法上应该写 |
| --- | --- | --- |
| `@Cacheable(value="train", key="#trainId")` | `railway:cache:train::1` | `@CacheEvict(value="train", key="#trainId")` |
| `@Cacheable(value="station", key="'list'")` | `railway:cache:station::list` | `@CacheEvict(value="station", key="'list'")` 或 `allEntries=true` |

两条铁律：

1. `value`（cache name）和 `key` 的**字符串要一模一样**，包括 `#trainId` 这种 SpEL 写法；
2. `key = "#trainId"` 里的 `trainId` 必须是**方法参数名**。用 IDEA 编译时如果没开 `-parameters`，请写成 `key = "#p0"` 或 `key = "#a0"`（按位置取第 1 个参数），最稳妥。

> 本项目 `value = "train"` / `"station"` 已经在 `CacheConfig` 里配好了 TTL（30 分钟 / 6 小时），
> `@CacheEvict` 不需要再写 TTL，它只负责删。

### 7.6 实测：缓存真的被删了吗

判断标准很简单：**改之前 Redis 里有 key，改之后没了，再查一次 key 又回来了（且值是新的）**。

```bash
# 0. 先让缓存生成
curl -s "http://localhost:200/api/train/1" -H "Authorization: Bearer <adminToken>"

# 1. 改车次（停运）
curl -s -X PUT "http://localhost:200/api/admin/train/1" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <adminToken>" \
  -d '{"status":0}'

# 2. 再查一次，应当看到 status=0（说明是重新查库，不是缓存）
curl -s "http://localhost:200/api/train/1" -H "Authorization: Bearer <adminToken>"

# 3. 验证完记得改回来
curl -s -X PUT "http://localhost:200/api/admin/train/1" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer <adminToken>" \
  -d '{"status":1}'
```

我在你的环境里实测的结果（用 `redis-cli` 直接看 key 是否存在）：

| 步骤 | 操作 | `EXISTS railway:cache:train::1` |
| --- | --- | --- |
| 1 | `GET /api/train/1`（status=1） | **1**（缓存已生成） |
| 2 | `PUT /api/admin/train/1 {"status":0}` | **0**（缓存被 `@CacheEvict` 删掉） |
| 3 | 再 `GET /api/train/1` | 返回 **status=0**（重新查库），随后 key 又变回 **1** |

车站那边（`allEntries`）同样实测：

| 步骤 | 操作 | `EXISTS railway:cache:station::list` |
| --- | --- | --- |
| 1 | `GET /api/station/list` | **1** |
| 2 | `PUT /api/admin/station/1 {"stationName":"北京","city":"北京"}` | **0**（整块 station 缓存清空） |
| 3 | 再 `GET /api/station/list` | 正常返回 5 条 |

> 验证小技巧：改车站时传**原来的值**（北京/北京），既能验证缓存清理，又不会真的改动数据。

### 7.7 常见坑

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 改了数据，缓存还在 | `@CacheEvict` 的 `key` 和 `@Cacheable` 写得不一样 | 两边 `value` + `key` 逐字符对照（见 7.3） |
| 注解完全不生效 | **同类内部调用**：`this.updateTrain(...)` 不走代理，注解被绕过 | 由 Controller 调 Service；或注入自己（`@Lazy`）后调用 |
| 删了详情，列表还是旧的 | 只删了一个 key，但列表接口缓存的是另一个 key | 列表用 `allEntries = true` |
| 方法报错了，缓存却被删了 | 用了 `beforeInvocation = true` | 默认 `false`（方法成功后才删）；确实需要提前删再显式打开 |
| 参数名取不到，SpEL 报错 | 编译时没保留参数名 | 改成按位置的 `key = "#p0"` |

## 10. 常见坑（含实测踩到的）

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `Could not write JSON: Java 8 date/time type LocalTime not supported` | 缓存序列化器没注册 `JavaTimeModule` | 用第 3.1 节的 `CacheConfig` |
| 缓存写进去读不回来，报 `Cannot construct instance of ...` | VO 只有 `@Builder`，没有无参构造 | VO 补 `@NoArgsConstructor @AllArgsConstructor` |
| `@Cacheable` 不生效 | 同类内部调用（`this.xxx`）、方法不是 public、类没被 Spring 管理 | 从外部 Bean 调用；确认启动类有 `@EnableCaching` |
| 改了库前端看不到变化 | 只加了 `@Cacheable`，没加 `@CacheEvict` | 写方法上补 `@CacheEvict`，key 写法与 `@Cacheable` 一致 |
| 看到"过时数据" | 缓存 TTL 还没到（车次 30 分钟） | 属正常；验证时手动 `DEL` 对应 key，别怀疑代码 |
| 互斥重建锁没释放 | 异常路径没 `finally` | 用 `try/finally` 包住并 `delete` |
| 对账把已卖的票"改回来"了 | 用 DB 覆盖了 Redis 的在途扣减 | 对账只收紧不放大（第 6 节代码已处理） |
| `/api/ticket/remain` 用了锁的 key | `queryRemain` 里写的是 `ticketLockKey` | P3 写 `buy` 时统一改成 `ticketStockKey` |
