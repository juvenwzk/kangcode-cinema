## 三、测试发现的 3 个问题（均已修复）

### ① 主代码编译不过（P4 半成品）

```
OrderController.java:[38,21] 找不到符号
  符号: 方法 cancel(java.lang.Long, java.lang.String)
```

`OrderController` 已写好 `/api/order/{orderNo}/cancel` 接口，但 `OrderService` 接口里 **`cancel` 只剩一行注释、方法声明没写**，`OrderServiceImpl` 也没实现 → 整个 server 模块编译失败。

**处理**：临时补了方法声明 + 占位实现（抛 `UnsupportedOperationException`）。  
⚠️ **写 P4 时要把它换成真正的实现**（状态置 2 + 发释放库存消息）。

### ② `buy()` 漏传 `travelDate` —— 会导致订单金额算成 0

`TicketServiceImpl.buy()` 里构建 `OrderCreateMessage` 时没带 `.travelDate(travelDate)`：

```java
// ❌ 修复前：travelDate 为 null
OrderCreateMessage.builder()
        .messageId(orderNo).orderNo(orderNo)
        .userId(userId).trainId(trainId)
        .seatType(seatType).ticketCount(count)
        .build()
```

**后果链**：消息里 `travelDate = null` → 消费者 `createOrder()` 按 `(trainId, travelDate, seatType)` 查座位 **查不到** → `price` 兜底为 0 → **订单以 0 元落库**，同时 DB 库存扣减的条件也匹配不上。

**处理**：补上 `.travelDate(travelDate)`。

### ③ 重复下单用错了返回码

```java
// ❌ 修复前：返回 400
throw new BusinessException(ResultCode.BAD_REQUEST);
```

按接口文档，重复下单应该是 **1002 `ORDER_REPEATED`「请勿重复下单」**。

**处理**：改为 `ResultCode.ORDER_REPEATED`。

> 另修正返回值文案里的错别字：「清在30分钟内」→「请在30分钟内」。

## 五、集成测试另外挖出的 4 个真问题（均已修复）

### ① `application-dev.yml` 里 Redis 地址写成了 `localhost`

Redis 实际在腾讯云 `43.166.0.94`（注释里也写着"与 youmall 使用同一套远程服务"），但 host 写的是 `localhost` → 应用起不来。  
**处理**：改为 `43.166.0.94`。

### ② Redis 密码配了，但那台 Redis 没设密码

启动时报：

```
ERR AUTH <password> called without any password configured for the default user
```

**处理**：把 `redis.password` 清空。

### ③ Lua 脚本遇到 `EMPTY` 空值标记直接崩（购票 500）

缓存里有 P2 写的防穿透标记 `EMPTY` 时，`tonumber("EMPTY")` 得到 **nil**，`nil < number` 抛错：

```
ERR user_script:13: attempt to compare nil with number
```

**处理**：脚本里先用 `local cur = tonumber(stock)`，判断为 nil（说明不是数字）就按"没票"返回 -1。

### ④ `RabbitMqConfig` 缺 JSON 消息转换器 → 订单永远落不了库（最严重）

生产者用 Java 原生序列化发消息，消费者侧反序列化被白名单拦下：

```
SecurityException: Attempt to deserialize unauthorized class com.kangcode.pojo.dto.OrderCreateMessage
```

**处理**：按 P3 文档 5.3 节补上 `Jackson2JsonMessageConverter` Bean。

### ⑤（附带）`StockServiceImpl.publish` 写缓存那步是空的

```java
String key = RedisKeyConstant.ticketLockKey(...);  // ❌ key 用错（该用 ticketStockKey）
return 0;                                          // ❌ key 定义了却没写缓存
```

**处理**：改用 `ticketStockKey` 并真正 `set` 上去（绝对值，天然幂等），返回值为放票后余票。

## 六、写 P4 测试时挖出的一个隐蔽坑（值得单独记一笔）

写 P4 的 13 个用例时，全部编译通过、但一跑就挂：

```
MybatisPlusException: can not find lambda cache for this entity [TrainOrder]
```

**原因**：代码里到处是这种写法——

```java
new LambdaUpdateWrapper<TrainOrder>().eq(TrainOrder::getStatus, 0)
```

MyBatis-Plus 要在**构造 wrapper 时**就把 `TrainOrder::getStatus` 解析成列名 `status`，
而这个解析依赖实体的元数据（`TableInfo`）。 正常启动 Spring 时由 MyBatis 自动初始化；
**纯 Mockito 单元测试里没有 Spring，元数据是空的** —— 于是抛出上面那个异常。

**这个坑最阴的地方在于它依赖测试的执行顺序**：

- 如果同一个 JVM 里**先跑了别的启动过 Spring 的测试类**（比如 `@SpringBootTest` 的 `SpringAmqpTest`），
  元数据会被顺带初始化，后面的测试**看起来一切正常**；
- 而**单独跑那一个类，立刻就挂**。

P3 的 `P3CreateOrderTest` 其实一直有这个问题，只是被全量跑的顺序"遮"住了。

**修法**：在会 new 出 Lambda Wrapper 的测试类里，`@BeforeAll` 手动初始化一次：

```java
@BeforeAll
static void initMp() {
    MpLambdaSupport.init(TrainOrder.class, TrainSeat.class);
}
```

配套的工具类 `server/src/test/java/com/kangcode/server/MpLambdaSupport.java` 就十几行，
内部调 `TableInfoHelper.initTableInfo(...)`。

> **教训**：测试"能过"不等于"是对的"——**顺序依赖型通过**是最危险的一种绿。
> 验证方法很简单：**单独跑每一个测试类**（`-Dtest=某个类`），而不是只跑全量。
