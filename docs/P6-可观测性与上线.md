## 1. 什么是可观测性

| 维度 | 解决什么问题 | 本项目用什么 |
| --- | --- | --- |
| **日志**（Logging） | 出了事，到底发生了什么 | logback + `log.info/error` |
| **指标**（Metrics） | 系统整体健康吗、有没有变慢 | Actuator + `/actuator/health` |
| **链路**（Tracing） | 一次请求经过哪些环节、慢在哪一步 | **TraceId**（轻量替代品） |

### TraceId 到底解决什么

一个请求会打很多行日志（拦截器、service、mapper…）。 并发一高，日志交错在一起，**根本分不清哪几行属于同一次请求**。

给每次请求生成一个 ID、并打进**每一行日志**，之后就能用这个 ID 把所有相关日志捞出来：

```bash
grep "a1b2c3d4" app.log      # 一次请求的完整轨迹，一秒钟捞全
```

这是最小的分布式链路追踪——生产上用 SkyWalking / Zipkin，原理是一样的。

## 2. 任务 6-1：TraceId（约 20 行代码）

### 2.1 改 `JwtInterceptor`（两处）

**文件**：`framework/src/main/java/com/kangcode/framework/security/JwtInterceptor.java`

**改动一**：在 `preHandle` **最开头**（在 `OPTIONS` 预检判断之前）加上生成 traceId 的逻辑。

> ⚠️ **必须放在最开头**。 如果放在后面，前面几行日志就没有 traceId；而且 `OPTIONS` 预检请求也该有。

```java
    @Override
    public boolean preHandle(HttpServletRequest request, HttpServletResponse response, Object handler)
            throws IOException {

        // ===== 新增：生成 traceId 并放进 MDC（后面每一行日志都会自动带上它）=====
        // 优先用上游（网关/前端）传来的，没有就自己生成 8 位
        String traceId = request.getHeader("X-Trace-Id");
        if (!StringUtils.hasText(traceId)) {
            traceId = UUID.randomUUID().toString().replace("-", "").substring(0, 8);
        }
        MDC.put("traceId", traceId);
        // ================================================================

        // 预检请求直接放行
        if (HttpMethod.OPTIONS.matches(request.getMethod())) {
            return true;
        }
        // ...（以下保持原样）
```

**改动二**：`afterCompletion` 里加 `MDC.clear()`。

```java
    @Override
    public void afterCompletion(HttpServletRequest request, HttpServletResponse response,
                                Object handler, Exception ex) {
        MDC.clear();            // ← 新增：不清的话，线程被复用时会串号
        UserContext.clear();    // ← 已有
    }
```

**需要补的 import**：

```java
import org.slf4j.MDC;
import java.util.UUID;
```

> `StringUtils` 这个类原来就有（`org.springframework.util.StringUtils`），不用重复加。

### 2.2 改 `logback-spring.xml`（在 PATTERN 里加 `%X{traceId}`）

**文件**：`server/src/main/resources/logback-spring.xml`

改动只有一处——`PATTERN` 里插入 `[%X{traceId}]`：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<configuration>
    <!-- 唯一改动：在 [%thread] 后面插入 [%X{traceId}] -->
    <property name="PATTERN"
              value="%d{yyyy-MM-dd HH:mm:ss.SSS} [%thread] [%X{traceId}] %-5level %logger{50} - %msg%n"/>

    <appender name="CONSOLE" class="ch.qos.logback.core.ConsoleAppender">
        <encoder>
            <pattern>${PATTERN}</pattern>
            <charset>UTF-8</charset>
        </encoder>
    </appender>

    <root level="INFO">
        <appender-ref ref="CONSOLE"/>
    </root>
</configuration>
```

### 2.3 验证

```bash
# 1. 登录拿 token
TOKEN=$(curl -s -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"demo","password":"123456"}' \
  | python -c "import sys,json;print(json.load(sys.stdin)['data']['token'])")

# 2. 随便调一个接口
curl -s http://localhost:8080/api/station/list -H "Authorization: Bearer $TOKEN" > /dev/null
```

控制台日志应该变成这样（多出 `[a1b2c3d4]` 这一段）：

```text
2026-10-15 22:40:00.123 [http-nio-8080-exec-1] [a1b2c3d4] INFO  c.k.s.c.StationController - ...
```

**连续调两次**，两次的 traceId 应该是**不同的**——这就对了（每次请求一个）。

> 想验证"串联"效果：调一个会打多行日志的接口（比如购票 `POST /api/ticket/buy`），
> 然后 `grep` 那个 traceId，能看到从拦截器到 service 的**完整一行行日志**。

## 3. 任务 6-2：Actuator

### 3.1 加依赖

**文件**：`server/pom.xml`，在 `<dependencies>` 里加：

```xml
        <dependency>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-actuator</artifactId>
        </dependency>
```

> 不需要写 `<version>`——父 pom（`spring-boot-starter-parent`）已经统一管理了。

### 3.2 打开端点

**文件**：`server/src/main/resources/application.yml`，在文件末尾加：

```yaml
management:
  endpoints:
    web:
      exposure:
        include: health,metrics      # 只暴露这两个。千万别写 * 
  endpoint:
    health:
      show-details: always           # 展开每个组件（db/redis/rabbit）的状态
```

> **为什么不能写 `*`**：`env`、`beans`、`heapdump`、`threaddump` 这些端点会泄露配置、甚至导出堆内存。
> 只暴露 `health,metrics`，需要别的再按需加。

### 3.3 验证

```bash
curl http://localhost:8080/actuator/health
```

预期返回：

```json
{"status":"UP","components":{
  "db":{"status":"UP"},
  "redis":{"status":"UP"},
  "rabbit":{"status":"UP"},
  "diskSpace":{"status":"UP"},
  "ping":{"status":"UP"}
}}
```

> **这个接口特别实用**——一次就能告诉你 **MySQL / Redis / RabbitMQ 三个中间件通不通**，比逐个手测快得多。
> 环境有问题时先打它，`status` 不是 `UP` 就看是哪个 component 挂了。

指标端点（可选）：

```bash
curl http://localhost:8080/actuator/metrics | python -m json.tool | head -30
curl http://localhost:8080/actuator/metrics/http.server.requests
```

## 4. 任务 6-3：上线清单

新建 `docs/上线清单.md`，照着填：

| 项 | 内容 |
| --- | --- |
| **环境变量** | `DB_HOST` / `DB_PORT` / `DB_NAME` / `DB_USER` / `DB_PASSWORD`、`REDIS_HOST` / `REDIS_PORT` / `REDIS_PASSWORD`、`RABBITMQ_HOST` / `RABBITMQ_PORT` / `RABBITMQ_USER` / `RABBITMQ_PASSWORD` |
| **启动命令** | `java -jar server-1.0.0-SNAPSHOT.jar --spring.profiles.active=prod` |
| **端口放行** | 只放业务端口（8080）；**Redis / RabbitMQ 绝不放公网**（见开发计划"坑 7"） |
| **健康检查** | 部署后先 `curl /actuator/health`，`status=UP` 才算成功 |
| **回滚步骤** | 保留上一个版本的 jar；回滚 = 换回旧 jar + 重启 |
| **日志位置** | 明确日志文件路径，出问题好查 |
| **数据库变更** | 本次上线有哪些 DDL/DML？ 有没有回滚脚本？ |

> **好消息**：`application-prod.yml` 已经全部用环境变量注入（`${REDIS_HOST:redis}` 这种写法），
> 所以你**不需要改配置文件**，只要在启动时提供变量即可。 例：
>
> ```bash
> java -jar server-1.0.0-SNAPSHOT.jar --spring.profiles.active=prod \
>   --REDIS_HOST=43.166.0.94 \
>   --RABBITMQ_HOST=43.166.0.94 \
>   --DB_HOST=127.0.0.1
> ```
>
> （Spring Boot 里**命令行参数优先级高于配置文件**，所以这样写最稳。）

## 6. 验收清单

| 检查项 | 标准 |
| --- | --- |
| TraceId 生效 | 日志每行都有 `[xxxxxxxx]`，两次请求的 id 不同 |
| TraceId 不串号 | 并发压一轮后，不同请求的 id 没有混在一起 |
| 健康检查 | `GET /actuator/health` 返回 `status=UP`，含 db/redis/rabbit |
| 端点最小暴露 | `include` 里只有 `health,metrics` |
| 上线清单 | `docs/上线清单.md` 六项齐全，且命令能照抄执行 |
| 回滚可用（选做） | 换回旧 jar 后服务能正常起 |

## 7. 常见坑

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 日志里 traceId 一直是同一个 / 串号 | `afterCompletion` 里没 `MDC.clear()` | **必须清理**——Web 容器用线程池，线程会被复用 |
| 日志里显示空的 `[]` | pattern 改了但代码没 `MDC.put`，或者 put 得比日志输出晚 | 确认 `MDC.put` 在 `preHandle` **最开头** |
| 部分日志有 traceId、部分没有 | 异步线程（如 `@Async`、MQ 消费者）里 MDC 不会自动传递 | 异步场景要在子线程里**手动** `MDC.put` 或者用 `TaskDecorator` 传递（本项目暂未涉及） |
| `/actuator/health` 返回 404 | 没加依赖，或端点没暴露 | 检查 `server/pom.xml` + `management.endpoints.web.exposure.include` |
| 健康检查一直 `DOWN` | 某个中间件不通 | 配合 `show-details: always` 看是哪个 component，再对照开发计划第十章排错 |
| 生产暴露了太多端点 | `include` 写成了 `*` | 只暴露 `health,metrics`；`env`/`beans`/`heapdump` 这类绝不暴露 |
| 加了 Actuator 后启动变慢 | 健康检查默认会探测所有组件 | 正常现象；不想探测某个组件可 `management.health.xxx.enabled=false` |
