# P1 认证与权限 · 开发文档（JWT + 拦截器版 · 第 2 周）

> 技术栈简化后，本项目**不再使用 Spring Security**，登录鉴权 = **JWT + Spring MVC 拦截器 + ThreadLocal 用户上下文**。
> 配套总计划：[开发计划.md](开发计划.md)

---

## 1. 为什么这样设计

| 对比项 | Spring Security（已移除） | 本项目方案（JWT + 拦截器） |
| --- | --- | --- |
| 学习成本 | 过滤器链、AuthenticationManager、SecurityContext 等概念多 | 只要会写 HandlerInterceptor 就能看懂 |
| 配置方式 | Java 配置类 + 大量约定 | 一个 `WebMvcConfig` + 一个拦截器类 |
| 权限控制 | `@PreAuthorize("hasRole('ADMIN')")` | 代码里 `UserContext.isAdmin()` 判断 |
| 依赖体积 | 引入整套安全框架 | 只需要 jjwt + Hutool BCrypt |

原理上两者是一回事：**都是"每个请求先验票，通过后把用户放进上下文"**，只是拦截器把这件事写得更直白。

| 类 | 位置 | 职责 |
| --- | --- | --- |
| `JwtUtils` | framework/security | 签发/解析 JWT（payload 放 userId、username、role） |

| `WebMvcConfig` | framework/config | 注册拦截器、配置放行路径 |
| `AuthServiceImpl` | server/service/impl | 注册、登录（Hutool BCrypt + 签发 token + 写 Redis） |
| `UserController` | server/controller | `/api/user/me`、`/api/user/logout` |

## 3. 流程图

![图 3 · 登录鉴权全流程（签发 token + 校验 token）](docs/diagrams/03-auth-flow.png)

**这张图是完整的两阶段**：

- **上半部分（①~⑥）**：登录怎么走 → 查库 → BCrypt 比对 → 查角色 → **签发 JWT** → **写入 Redis** → 返回。
  为什么要写两份？因为 JWT 签发后**无法撤销**，为了支持登出和顶号，额外在 Redis 存一份当前有效的 token 做比对。
- **下半部分**：后续每次请求怎么校验 token。注意它有**两条 401 分支**，message 不同（见下面 3.2）。

下面用文字再列一遍关键判断点，方便你对照代码逐行看：

### 3.1 登录

```
POST /api/auth/login {username, password}
  │
  ▼
AuthServiceImpl.login
  ├─ 按用户名查 sys_user → 不存在 → LOGIN_ERROR(1006)
  ├─ Hutool BCrypt.checkpw(明文, 库里的密文) → 失败 → 1006
  ├─ 查角色（sys_user_role → sys_role）→ role = ADMIN / USER
  ├─ JwtUtils.createToken(userId, username, role)  ← 角色写进 token
  ├─ SET user:token:{userId} = token  EX 720分钟   ← 登出/踢人靠它
  └─ 返回 {token, userId, username, nickname, role}
```

### 3.2 请求鉴权

```
任意 /api/** 请求
  │
  ▼
JwtInterceptor.preHandle
  ├─ OPTIONS 预检 → 直接放行
  ├─ 取 Authorization: Bearer xxx → 没有 → 401 JSON
  ├─ JwtUtils.parseToken → 签名错/过期 → 401 JSON
  ├─ 取 Redis user:token:{userId} → 不存在或不等于本次 token → 401 JSON（已登出/被顶号）
  ├─ UserContext.set(LoginUser{userId, username, role})
  └─ 放行 → Controller
        │
        └─ 业务代码：UserContext.userId() / UserContext.isAdmin()
  ▼
afterCompletion → UserContext.clear()   ← 防止线程池串号
```

### 3.3 放行规则

```
放行：/api/auth/login、/api/auth/register、/error
拦截：/api/** 其它全部
```

## 4. 关键代码

### 4.1 签发 token（JwtUtils）

```java
public String createToken(Long userId, String username, String role) {
    Date now = new Date();
    Date expire = new Date(now.getTime() + expireMinutes * 60 * 1000);
    return Jwts.builder()
            .setSubject(String.valueOf(userId))
            .claim("username", username)
            .claim("role", role)                 // 角色进 token，拦截器直接取
            .setIssuedAt(now)
            .setExpiration(expire)
            .signWith(SignatureAlgorithm.HS256, secret.getBytes(StandardCharsets.UTF_8))
            .compact();
}
```

### 4.2 拦截器（JwtInterceptor）

```java
@Override
public boolean preHandle(HttpServletRequest request, HttpServletResponse response, Object handler) throws IOException {
    if (HttpMethod.OPTIONS.matches(request.getMethod())) { return true; }

    String token = resolveToken(request);
    if (!StringUtils.hasText(token)) { writeUnauthorized(response, "未登录或登录已过期"); return false; }
    try {
        Claims claims = jwtUtils.parseToken(token);
        Long userId = Long.valueOf(claims.getSubject());
        String username = claims.get("username", String.class);
        String role = claims.get("role", String.class);

        String cached = stringRedisTemplate.opsForValue().get(RedisKeyConstant.userTokenKey(userId));
        if (cached == null || !cached.equals(token)) { writeUnauthorized(response, "登录已失效，请重新登录"); return false; }

        UserContext.set(LoginUser.builder().userId(userId).username(username).role(role).build());
        return true;
    } catch (Exception e) {
        writeUnauthorized(response, "未登录或登录已过期");
        return false;
    }
}
```

### 4.3 注册拦截器（WebMvcConfig）

```java
registry.addInterceptor(jwtInterceptor)
        .addPathPatterns("/api/**")
        .excludePathPatterns("/api/auth/login", "/api/auth/register", "/error");
```

### 4.4 业务取当前用户

```java
Long userId = UserContext.userId();          // 下单、查订单
if (!UserContext.isAdmin()) {                // 管理接口
    throw new BusinessException(ResultCode.FORBIDDEN);
}
```

### 4.5 密码加密（Hutool BCrypt）

```java
// 注册
user.setPassword(BCrypt.hashpw(request.getPassword(), BCrypt.gensalt()));
// 登录
BCrypt.checkpw(request.getPassword(), user.getPassword());
```

> Hutool 的 BCrypt 与 Spring Security 的 `BCryptPasswordEncoder` 生成的都是标准 `$2a$` 哈希，**历史数据可以继续用**。

## 5. 接口文档

| 方法 | 路径 | 鉴权 | 说明 | 返回 |
| --- | --- | --- | --- | --- |
| POST | /api/auth/register | 否 | 注册（自动登录） | token + 用户信息 + role |
| POST | /api/auth/login | 否 | 登录 | token + 用户信息 + role |
| GET | /api/user/me | 是 | 当前登录用户 | userId / username / role |
| POST | /api/user/logout | 是 | 登出（删除 Redis token） | null |
| GET | /api/admin/ping | 是 + ADMIN | 管理员权限校验 | "admin ok" |

### 请求/响应示例

```json
// POST /api/auth/login
{ "username": "demo", "password": "123456" }

// 成功
{ "code": 200, "message": "操作成功",
  "data": { "token": "eyJhbGciOiJIUzI1NiJ9...", "userId": 4, "username": "demo", "nickname": "演示用户", "role": "USER" } }

// 密码错误
{ "code": 1006, "message": "用户名或密码错误", "data": null }

// 未登录访问业务接口（HTTP 401）
{ "code": 401, "message": "未登录或登录已过期", "data": null }

// 普通用户访问 /api/admin/ping（HTTP 200 + 业务码 403）
{ "code": 403, "message": "无权限访问", "data": null }
```

### 验证命令

> **端口约定**：后端直接跑在 **8080**（`server.port`）。 下面的命令都用 8080。
> 如果前端是走 nginx 的 200 端口反代 `/api` → 后端 8080，那用 200 也行，但**前提是 nginx 在跑**；直接用后端调试建议统一用 8080。

```bash
BASE=http://localhost:8080

# 1. 登录拿 token
curl -X POST $BASE/api/auth/login -H "Content-Type: application/json" \
  -d '{"username":"demo","password":"123456"}'

# 2. 不带 token → 401
curl -i $BASE/api/train/page

# 3. 带 token → 200
curl $BASE/api/train/page -H "Authorization: Bearer <token>"

# 4. 普通用户访问管理接口 → 403
curl $BASE/api/admin/ping -H "Authorization: Bearer <token>"

# 5. 登出后原 token 失效 → 401
curl -X POST $BASE/api/user/logout -H "Authorization: Bearer <token>"
```

管理员账号：`admin / admin123`（注册后把 `sys_user_role.role_id` 改成管理员角色即可；具体做法见开发计划 6.2 第 ③ 节）。

## 6. 常见坑

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 登录成功但接口还 401 | token 没带上 / 前缀不是 `Bearer ` | 前端 `api.js` 统一加 `Authorization: Bearer <token>` |
| 登出后 token 还能用 | 拦截器没比对 Redis | 检查 `cached.equals(token)` 这段 |
| 换个接口突然变成别人的身份 | `UserContext` 没清理 | 已在 `afterCompletion` 调 `clear()`，别在别处提前清 |
| 密码校验失败 | 用了 `equals` 比较密文 | 必须用 `BCrypt.checkpw` |
| 管理接口 403 | 用户角色不是 ADMIN | 查 `sys_user_role` 并改成 role_id=1 |
