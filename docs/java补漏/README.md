# Java 补漏 · 学习路线

> 这份材料是给**已经能写 Spring Boot 业务代码、但没系统学过 Java 底层**的人用的。
> 判断标准不是"看了多少"，而是"能不能不看资料讲出来"。

---

## 0. 先搞清楚你的真实位置

我在你项目里搜了一圈，结果是这样的：

| 能力项 | 你项目里的实际情况 |
| --- | --- |
| `synchronized` / `volatile` / `Atomic*` | **0 处** |
| 线程池 / `CompletableFuture` | **0 处** |
| `HashMap` / `ConcurrentHashMap` / `HashSet` | **0 处**（只有 1 个 `ArrayList`） |
| 自定义泛型（`<T>`、通配符） | **0 处**（只用了 `BaseMapper<T>`） |
| `Optional` / `record` / `var` | **0 处** |
| 自定义异常 | **1 个**（`BusinessException`） |
| Stream | **1 处**（`listMyOrders` 里的 `map + collect`） |

**这不是你偷懒** —— 你用 Redisson、RabbitMQ、MyBatis-Plus 这些组件，把"需要手写底层"的地方都绕过去了。
一个能跑通的业务系统，本来就不需要你天天写 `synchronized`。

**但这带来一个问题：你的项目标签是"高并发"，而代码里没有一行并发代码。**

面试官看到"高并发购票系统"，一定会往 JUC 问。你现在的答案只有"我用了分布式锁"，
被追问一句"**那单机情况下你怎么保证线程安全？**"就卡住了。

## 2. 每一章的结构（固定）

我写每一章都按这个顺序，你读的时候也照这个顺序理解：

```
① 现象      先看一段代码 / 一个场景，你能看到"出问题了"
② 为什么    原理，讲到你能自己推出结论为止
③ 怎么写    正确写法，以及"不这么写会怎样"
④ 自测      3~5 道题，能答出来才算过
```

> **不要跳着看第 ③ 步。** 直接抄正确写法，等于又走一遍"能跑通但不懂"的老路。

## 4. 学习方式：不要只看

你的项目本身就是最好的练习场。三个"既练手又加分"的改造：

| 改造 | 练到什么 | 面试价值 |
| --- | --- | --- |
| 对账任务改线程池分批 | 线程池参数、拒绝策略、`Future` | "我把串行对账改成了并行分批，耗时从 X 降到 Y" |
| 余票查询加本地缓存（Caffeine） | 并发容器、可见性 | "我在 Redis 前面加了一层本地缓存，QPS 提升 X" |
| 把 `buy()` 的异常回补逻辑重写 | 异常语义、幂等 | "我发现了一个自己写的设计缺陷" |

**做完任何一个，都在 `docs/` 里留一段"设计决策记录"**：为什么改、代价是什么。这比刷十道题有用。

## 5. 一个必须建立的意识

> **"能跑通"和"在并发下正确"是两件事。**

你现在的代码在单人测试下 100% 正确。但把并发调到 12，就出现了 5 个"抢锁超时"；
如果把锁去掉，立刻会超卖。**这就是并发问题的特点：它不报错，只是偶尔算错。**

所以学并发不是背概念，是训练一种**"这段代码在多线程下会不会错"的直觉**。
