## 项目经历

### 电影票购票系统 · 高并发余票扣减与一致性　|　个人项目　|　2026.03 - 2026.10

**技术栈**：Java 17、Spring Boot 2.7、MyBatis-Plus、MySQL 8、Redis、Redisson、RabbitMQ、nginx

**项目描述**：影片查询、下单、支付、退票完整闭环，重点解决高并发扣减与异步一致性。

- **防超卖四层防护**：同一用户 30 秒幂等键 → Redisson 分布式锁（粒度：场次 + 日期 + 票种）→ Redis Lua 原子判断并预扣 → MySQL `WHERE remain >= n` 兜底。12 / 15 人并发抢 10 张票，账目全部对平，无超卖、无负库存。
- **缓存三兄弟**：空值缓存（60s）防穿透、互斥重建锁防击穿、TTL 600s + 0~60s 抖动防雪崩。关掉任一机制，50 次请求的数据库访问由 5 次升至 54 次（10.8 倍）。
- **异步最终一致**：下单接口只做「预扣 + 发 MQ」，订单与明细落库、DB 库存扣减交给消费者；TTL + 死信队列实现 30 分钟未支付自动关单并回补库存，配 5 分钟对账修正偏差。
- **订单状态机**：0 待支付 → 1 已支付 → 4 已退票，0 → 2 已取消；所有流转用带源状态条件的 UPDATE + 影响行数判断，避免「先查后改」的并发窗口，天然获得支付回调与重复退票的幂等性。
- **性能**：缓存命中时 1000 次余票查询仅 4 次落库（挡掉 99.6%）；20 并发 1430 QPS / P99 32ms，100 并发 0 错误。
- **工程**：traceId 全链路可追踪，Actuator 一键确认三件中间件连通；45 个 Mockito 单测覆盖幂等、锁竞争与非法状态流转。
